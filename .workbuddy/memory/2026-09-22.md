## v5：rar 也解开了（老板追问后）

**关键突破：Windows 自带的 `C:\Windows\System32\tar.exe` 是 bsdtar(libarchive)，能直接解 rar！**
```bash
/c/Windows/System32/tar.exe -tf "xxx.rar"                     # 列内容
/c/Windows/System32/tar.exe -xf "xxx.rar" -C "<目标目录>"      # 解压
```
- Git Bash 自带的 `/bin/tar` 是 GNU tar，**不支持 rar**（报 "This does not look like a tar archive"）
- 本机另有 **7-Zip**：`C:\Program Files\7-Zip\7z.exe`（但 7z 命令行读 rar 会报"系统找不到指定的路径"，**bsdtar 更可靠**）
- ⚠️ bsdtar 解 rar 会报 `Parsing filters is unsupported` 但**实际解出成功**

## v10：附件上传 —— 老板提醒「别造轮子」，果然有现成命令

**老板原话**：「飞书技能我很全的，附件上传怎么做找一找，或者连接器，别自己造轮子」

### 结论：`lark-cli` 自带 `base +record-upload-attachment`
```bash
lark-cli base +record-upload-attachment \
  --base-token <BASE> --table-id <TID> --record-id <REC> \
  --field-id 文件 --file ./相对路径.pdf --as user
```
一条命令完成「上传 + 拿 file_token + 回填单元格」。
- 单格 ≤50 个文件、单文件 ≤2GB，**>20MB 自动 multipart**
- `--file` 必须**相对路径 + cwd 对齐**（绝对路径报 "not a valid path on this platform"）
- **已实测成功**：喜多 ISO9001 → 记录 `recvvVJcq6RX94`，file_token `EGg0bAEFGo1QoJxuQjecbELynkd`

### 我的弯路（记下来别再走）
先自己拼了 `POST /drive/v1/medias/upload_all`（`parent_type=bitable_file` + `parent_node=<base>`）
→ 能跑通、拿到 file_token，但**完全没必要**。正确顺序是：
**`lark-cli base --help | grep -i attach` 先查现成命令**。

同时确认：
- `+record-update` **不存在**（只有 `+record-upsert`）；报错信息里会提示可用命令，**要读提示**
- `drive +upload` 只能进云空间，**不能**写 Base 附件字段
