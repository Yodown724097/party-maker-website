### 四类规范缺失（附实测数据）

**① 组件没有单一事实源（SSOT）** ← 汉堡菜单修很久的直接原因
改一次导航要动 **4 处**：首页 HTML + `page()` 模板 HTML + 首页内联 CSS + `site.css`
42 条 CSS 规则两处各存一份

**② class 命名无契约（同名不同义）**
| class | 首页含义 | site.css 含义 |
|---|---|---|
| `.ft` | flex 排列容器 | navy 背景块 + 内边距 |
| `.hd` | 布局（flex/gap/高度） | 外观 + sticky + z-index |
| `.shot` | 卡片外观（背景/边框/圆角） | 只有 `margin:0` |
→ 规则被拆到两处，**谁都不知道完整定义在哪**

**③ 设计令牌未强制 + 数值漂移（21 条真实差异）**
- `.btn-gold`：首页 = 金底深字 / 子页 = 藏青底金字 —— **同名按钮两种视觉**
- `.logo .mark`：30px vs 28px；`.logo` font-size 1.15 vs 1.1rem
- `.btn`：padding 14px 30px vs 13px 28px
- `.shot figcaption`：首页硬编码 `#9FB0C9` / 子页走 `var(--ab-ink-2)`

**④ 方向属性约定未强制（RTL 会坏）**
- 首页 `.nav-bars::before/::after` 用 `left:0` / `top:6px`（物理属性）
- site.css 用 `inset-inline-start:0` / `inset-block-start:6px`（逻辑属性）
- `ARCHITECTURE.md` 明确写「⛔ 禁用 left/right」→ **首页违反自己的硬约束**
- 后果：做阿语 RTL 版时**首页汉堡图标不镜像**（子页会）

### 更准确的诊断

> 不是"没有设计规范"——`ARCHITECTURE.md` 里其实写了不少正确的（三问、复用清单、逻辑属性约束）。
> 问题是 **规范只管「新建页面/组件」，没管「修改已有组件」**，而且**没有机制强制**（全靠自觉）。

昨天的汉堡菜单正好是"改已有组件"，落在这个盲区里。

### 一、样式统一 —— 找到双实现的真身

**首页与子页连 HTML 结构都不同**：
```
首页  <header><div class="wrap hd">
子页  <header class="hd"><div class="wrap hd-in">
```
`.hd` 在两处指代**不同层级**（首页=内层布局容器，子页=外层外观），页脚同理
（`<footer><div class="wrap"><div class="ft">` vs `<footer class="ft"><div class="wrap"><div class="ft-in">`）。
→ 改一次导航要改两处，漏一处就出事。

**做法**：首页 HTML 改名对齐子页 → 首页 `<style>`（111 条）并入 site.css →
**元素选择器限定作用域**（`section{}`→`.home section{}`、`h1{}`→`.hero h1{}`、

# 第八轮：favicon / PWA 图标接入

## 素材与结论

老板给的 `C:\Users\Administrator\Pictures\favicon_io`。
**答复：不能直接用** —— 全是 **JPEG**（favicon_io 本该导出 PNG）：
- Safari / iOS 对 JPEG favicon 支持不可靠，而很多买家就用 iPhone/Safari
- `apple-touch-icon` 与 webmanifest 的 `icons` 规范上要求 PNG

而站上**此前完全没有 favicon**（<head> 里没有 icon 链接、也没有图标文件）。

## 处理（全部从 512 母版重采样）

`favicon.ico`（16/32/48 内嵌）+ `assets/favicon-16/32.png` + `apple-touch-icon.png`
(180) + `android-chrome-192/512.png` + 构建生成的 `site.webmanifest`。

**两次实测代替拍脑袋**：
- 徽记（两侧月牙 + 中间灯笼）占画布 **90%×69%**，缩到 16px 约 14px 宽；
  可见度与自带 16px 版实测相当（非底色像素 18.8% vs 18.4%）→ 不需裁切放大
- 侧边留白仅 **5%** < Android maskable 要求的 10%
  → manifest 只声明 `purpose:"any"`（声明 maskable 会被圆形遮罩裁掉月牙）

> 另：我用「与模糊滤波的差异」当噪声指标，结果 16px 时源图"更干净" ——
> **那个指标把细节和噪点混在一起了，不能用来下结论**。换成"非底色像素占比"才对。

## 接入（延续唯一来源）

- `theme-color` / manifest 的 theme_color **从 site.css 的 `--navy` 读**（`css_token()`）
